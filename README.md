## Цель проекта

Цель проекта — формализовать терминосистему статьи в виде графа, выявить её структурные и логические несовершенства с помощью программного анализа, а затем предложить более последовательную и логически непротиворечивую модель.

Работа строится в два этапа:

**AS-IS** — максимально близкое воспроизведение исходной терминосистемы статьи.

**TO-BE** — переработанная структура, в которой устраняются найденные проблемы.

Главная идея проекта заключается в том, чтобы не ограничиваться субъективной оценкой терминосистемы, а формализовать критерии её анализа и автоматически находить потенциальные дефекты графа.

## Исходная таблица

В качестве исходного представления терминосистемы используется Excel-таблица, содержащая **69 терминов**.

Для каждого термина задаются следующие поля:

| Поле                        | Назначение                                                                             |
| --------------------------- | -------------------------------------------------------------------------------------- |
| `Термин`                    | исходное понятие из статьи                                                             |
| `Мета-Класс (L1)`           | верхний уровень предметной области: «Спорт» или «Физическая культура»                  |
| `Функциональный класс (L2)` | семантическая группа понятия, например субъекты, виды спорта, инфраструктура, процессы |
| `Родительский узел`         | понятие или категория, с которой связан термин                                         |
| `Тип связи`                 | характер отношения между термином и родителем                                          |
| `Критерий деления`          | признак, по которому термин выделяется внутри классификации                            |
| `Дефект логики / Казус`     | предварительное содержательное замечание о возможной проблеме                          |

В таблице используются несколько типов отношений:

* `Is-A` — отношение «является разновидностью»;
* `Part-Of` — отношение «является частью»;
* `Role` — ролевая принадлежность;
* `Attribute` — характеристика или связанный атрибут;
* `Root` — корневой элемент структуры.

После загрузки данных было получено следующее распределение:

* `Is-A` — 38 связей;
* `Role` — 11;
* `Part-Of` — 9;
* `Attribute` — 7;
* `Root` — 4 записи в исходной таблице.

## Подготовка графа

Исходная таблица автоматически обрабатывается Python-программой.

На первом этапе данные очищаются и проверяются. Затем они преобразуются в две отдельные структуры:

* `nodes.csv` — список узлов;
* `edges.csv` — список отношений между узлами.

Кроме 69 терминов статьи, были выделены **5 вспомогательных узлов**, которые используются только для структурирования графа, например:

* «Физические лица»;
* «Организации и объединения»;
* «Коллективные субъекты»;
* «Физические / Юр. лица»;
* «Мероприятия и события».

Они отдельно маркируются как `helper`, чтобы программа могла отличать элементы исходной статьи от категорий, введённых при формализации.

В результате AS-IS граф содержит:

* **74 узла**;
* **67 рёбер**;
* **69 исходных терминов**;
* **5 вспомогательных категорий**.

## Первые результаты анализа

Граф строится как ориентированный граф с использованием библиотеки `NetworkX`.

Первичный структурный анализ показал, что терминосистема состоит из **7 слабосвязных компонент**.

Наиболее нагруженными родительскими узлами являются:

* `Спорт` — 10 непосредственных потомков;
* `Физические лица` — 8;
* `Организации и объединения` — 7;
* `Физическая культура` — 6;
* `Коллективные субъекты` — 5.

Особое внимание представляет узел `Спорт`, поскольку непосредственно с ним связаны понятия, выделенные по разным основаниям.

Например:

```text
Спорт
├── Детско-юношеский спорт
├── Массовый спорт
├── Профессиональный спорт
├── Спорт высших достижений
├── Студенческий спорт
├── Спортивная подготовка
├── Спортивные мероприятия
└── Спортивная санкция
```

Здесь одновременно смешиваются разные основания классификации и даже разные семантические категории.

Например:

* детско-юношеский спорт выделяется по возрасту;
* студенческий — по образовательному контексту;
* профессиональный — по профессиональному или экономическому статусу;
* массовый — по характеру и цели участия;
* спорт высших достижений — по уровню результата.

Таким образом, непосредственные потомки одного узла не обязательно являются взаимоисключающими классами.

Один объект может одновременно относиться, например, к студенческому, массовому и любительскому спорту.

Это свидетельствует о возможном **смешении независимых оснований классификации**.

## План программного анализа

Следующий этап проекта — автоматическая диагностика терминосистемы.

Планируется реализовать несколько групп проверок:

### Структурный анализ

Поиск:

* циклов;
* изолированных узлов;
* несвязных компонент;
* перегруженных родительских узлов;
* противоречий между объявленным типом узла и его положением в графе.

### Анализ классификации

Проверка единства основания деления.

Например, программа должна определить, что непосредственные подклассы `Спорта` выделены одновременно по возрасту, образовательному статусу, профессиональному статусу, цели участия и уровню достижений.

### Семантический анализ

Проверка совместимости типов узлов.

Например, необходимо отличать:

* вид деятельности;
* процесс;
* событие;
* организацию;
* физическое лицо;
* нормативную меру.

Это позволит обнаруживать случаи, когда в одной таксономической ветви оказываются сущности разных категорий.

### Анализ определений

Планируется отдельно построить граф зависимостей между текстами определений.

Он позволит находить циклические определения вида:

```text
Спорт → Вид спорта → Спорт
```

## Итоговая цель

После анализа AS-IS модели будет построена TO-BE онтология.

При этом новая модель будет проверяться **тем же набором алгоритмов**, что и исходная.

Таким образом, улучшение структуры можно будет показать не только визуально, но и количественно, например:

```text
AS-IS:
31 диагностическая проблема
12 высокой критичности

TO-BE:
6 диагностических проблем
0 высокой критичности
```

В результате проект представляет собой систему автоматизированного анализа терминосистемы: от исходной статьи и её формализации до обнаружения структурных и семантических проблем и последующего рефакторинга онтологии.
